# deployments/ — address books (data, not code)

`<chainId>.json` is written by `script/DeployAll.s.sol` at the end of a broadcast and is the single source of
truth for every consumer (SDK chain definition, indexer, API, docs site, `tools/*`). Fields: chain id, deploy
block/timestamp, deployer, Admin Safe, treasury, timelock (+ delay), oracle `launchTs`, commit-reveal ages,
compiler pins, `contracts{name: address}`, `bytecodeHashes{name: keccak256(runtime code)}`, the TLD table
(`label, node, namespaceId, registrar, controller, status`) and the path of the forge broadcast log holding
every creation tx hash. `5042002.json` = Arc testnet (WP-115, produced by the CEO's live run of the script);
`5042.json` = Arc mainnet (M4). `*.dry-run.json` files (fork rehearsals with `ARCNS_DRY_RUN=1`) are ignored.

Market stack (WP-124, three phases — `docs/runbooks/market-deploy.md`): `script/DeployMarket.s.sol --broadcast`
appends a `market{ArcNSMarket, NameLocks, RecordDelegate, TextRecords, AttestationRegistry, IntegratorRegistry,
Vouchers}` object to the same `<chainId>.json` (key-scoped write; the M1/M2 keys are never rewritten). Without
`--broadcast` it writes `<chainId>.market-dry-run.json` instead (ignored). `<chainId>.market-grant.json` is the
phase-2 governance payload (`script/GrantMarketRole.s.sol`): the `TimelockController` operation that grants
`MARKET_ROLE` on `HandleRegistry` to the market, its op id and the Admin Safe `execTransaction` inputs — committed,
deterministic (same market address ⇒ same bytes), regenerated by the live run and expected to reproduce byte for byte
except for the `state` block.

Verification after any deploy: `forge script script/VerifyRoles.s.sol --rpc-url $ARC_RPC_URL` prints
`ROLES_VERIFIED` (M1/M2) and `forge script script/VerifyMarketRoles.s.sol --rpc-url $ARC_RPC_URL` prints
`ROLES_VERIFIED` for the market stack once the phase-2 timelock operation has executed (before that: `ROLES_FAILED`
with one `FAIL` line naming the missing `MARKET_ROLE` grant); `npm --prefix tools run verify-pricing` prints one `MATCH` per namespace;
`deploy/BUILD.md` explains how to compare `bytecodeHashes` with a local build.
